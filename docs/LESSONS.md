## 10-26 3:50pm ET · Chris's catch: an Amazon AWS scraper pulled ~70K card pictures in 80 minutes; bot watch never saw it
- What: Chris found a ~25K spike on the Vercel Firewall chart (~2:15-3:35pm ET): "you are supposed to be protecting from bots, this is like the 4th time you failed". One Amazon network (AS14618, us-east-1), 32-76 addresses, two Node.js TLS fingerprints, half the requests named "probe-image-size/7.4.0", half a fake "Chrome/124 Windows", ~99% /pics/ (the same promo tiles ~345 times each). Not our code (no probe-image-size in our dependencies, no Chrome/124 in src/ or scripts/).
- Why it got through: (1) bot watch only counted CARD PAGES as crawling, so a picture-only scraper read "0% card pages -> ok"; (2) Amazon sat on bot watch's "alert only, too broad" list; (3) GitHub ran bot watch ~8 times in 24 h instead of 48; (4) no firewall rule touched rented servers outside /api/auth/, and the /pics/ limit is per address (3,000/min) while the pool spread out.
- Taught: a protection that waits for one known pattern misses the next pattern. The rented-server class needed a wall of its own, with the allowed list as the exception, not one rule per bot after Chris spots it.
- Changed (firewall, live): v51 deny AS14618 + its two fingerprints (3:35pm; refused 108 / 89 / 36 per 5 min after); v52 "Scrapers: cloud + hosting networks need a browser check (challenge)" (scripts/_fw-cloud-challenge.mjs): Amazon, Google Cloud, Azure + 65 hosting/proxy companies (every ASN RIPEstat-checked; AS8100 dropped = an Australian ISP) must pass Vercel's JavaScript check; allowed bots skip it only from their own network (Google names only on Google Cloud, Bing/OpenAI names only on Azure), so do our tools (cardflip-uptime, cardflip-smoke, CardFlip/1.0 video renderer, vercel-cron), machine paths, robots.txt and the smoke pass header; a real person on a VPN passes once and browses on. v53 Reflectionbot (~3.9K card pages/day from Google Cloud), ElevenlabsCrawler, Lightpanda, KeenableBot denied by name (scripts/_fw-ai-crawlers.mjs). Smoke re-run 3:45pm = 16/16 under the new rule.
- Changed (code, commit only, rides the next push): bot watch also flags picture-only scrapers (>=80% /pics/ with <1% app code or /api/ calls; real visitors measured 2-62% app and <=16% pictures), blocks Amazon / Google Cloud / Azure pairs unless the top agent is an allowed bot, runs 4 times an hour (dry run on today's traffic flagged both Amazon pairs); prod-smoke sends the pass header on /admin + sitemaps; robots.txt turns the 4 new bots away.
- Open: the 1:10pm publisher timeout, 1:16pm uptime card-search timeout and 2:54pm smoke "featured stage cards" timeout came at quiet times (~1K requests in 45 min around 1pm) = not this bot; checked next. Vercel's own Bot Protection (verified-bot aware, also catches non-browser clients on home networks) is still Off: turn it on in log mode and measure before challenge.
