# Whole-site review, 2026-10-19

Seven read-only passes (scanner, app pages, public card pages, marketing + auth, pricing libs + APIs, admin, design) over the ~100k lines in src/, plus my own spot checks of the biggest claims against the code. About 270 findings in all. Nothing was changed. The full per-area lists follow the summary.

Feature freeze holds: everything below is a bug, a polish item, or a cleanup. No new features.

## The short version

Scored well: auth and billing (hashed single-use reset tokens, idempotent Stripe webhook, every API route gated), the price guard, the public card pages (canonical redirects, ISR, metadata), admin auth, and the overall look (one dark background, one brand colour, one header, one toast system).

Where it slipped during the Opus week:
- Rules that live in one place drifted into three. The default printing is ranked two different ways, there are six money formatters, four add-to-watchlist paths, seven hand-rolled copies of the shared bottom sheet, eight near-identical "solid dark" colours.
- Leftovers of removed features are still live: the on-device OCR fallback (rule says no OCR), the dead "binder page" capture mode, the dead auto game switch, dev-only outline-debug code in the production bundle.
- Phone ergonomics: 229 uses of 10-11px text, grey text at 3.7:1 contrast, and most controls in the app chrome (tabs, header pills, Clear, Done, footer links, breadcrumbs) at 28-36px instead of 44px.
- Blanks where the "every card shows a price" rule should apply: search results, public profiles, the set list (drops flagged cards entirely), the sticky price bar.
